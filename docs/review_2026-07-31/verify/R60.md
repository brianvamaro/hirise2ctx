## Verdict reasoning

Category **(f) real and correctly stated**. Four separate lines of evidence agree and I could not break any:

1. **Chronology.** `dataset_v2/modeling_slim_{predictions,summary}.parquet` are 2026-06-03 16:20;
   `docs/modeling_slim.md` is 2026-06-08, `docs/classification_slimmer.{md,pdf}` 2026-06-09
   (`19aa19b`, "for report submission"); the sign fix and full label regeneration are 2026-06-10
   (`dataset_v2/labels/*` all 2026-06-10 18:19-18:24, sidecar `written_at_iso` 2026-06-11T01:24Z).
   The slim run was never re-run — the parquets are still the Jun-3 files.
2. **The published table is machine-generated from the stale parquet**, so it cannot have been silently
   refreshed: `scripts/probes/_modeling_slim_figures.py:14` `SUM = pd.read_parquet(ROOT / "dataset_v2" /
   "modeling_slim_summary.parquet")` and :23-35 burn `median=…, frac>=0.70 = …, frac<0.50 = …` into the
   figure title. Every value in `docs/modeling_slim.md:265-272` matches that parquet to the digit.
3. **The delta is the coreg fix and nothing else.** The only sidecar keys that differ between the frozen
   pre-fix copy and the live labels are `coreg_shift_m` (sign of `dy`), the tile-scale list (S=128
   dropped), the window's `finest_grid_cells`, paths and timestamps. `detection_filters`, `grid_anchor`,
   `mosaic_row_origin`, `mosaic_col_origin`, `subpixel_factor`, `binary_*_threshold` and
   `eligibility_rule` are **identical**, and the `(obs_id, ti, tj)` join matched all 33 102 banked rows
   with zero misses and zero duplication — so the tile grid is the same grid and only the label values
   moved. The displacement fingerprint above then pins the movement to the sign error specifically.
4. **No caveat exists.** `grep -in "coreg|stale|2026-06|superseded|caveat"` over `docs/modeling_slim.md`
   returns only false positives ("signal", "reproducible"); over `docs/classification_slimmer.md` it
   returns **nothing**. `docs/index.md:16` still presents the document as "Used as the model writeup for
   the project report. Written 2026-06-03." with no provenance warning.

Things I tried in order to kill it, and why they failed:
- *Maybe the docs were re-generated after the fix from a re-run that wasn't saved?* No — the numbers match
  the Jun-3 parquet exactly, and re-scoring on corrected labels gives different values, so the docs are
  provably the stale generation.
- *Maybe part of the label delta is a config change, making the "sign fix" attribution wrong?* Ruled out
  by (3): filters and grid provenance are byte-identical, and the delta is a pure rigid southward
  translation of 2·dy with no x-component.
- *Maybe the rescore is invalid because features are stale too?* The coreg shift is applied only to the
  HiRISE polygons (`src/labeling.py:85-93` `out.geometry = out.geometry.translate(...)`, called at :475),
  after the CTX window is fixed — so CTX-side features are untouched by the fix. The rescore changes only
  the test labels, which is exactly the quantity the fix corrected. (Features are one generation old for
  a *different* reason — the Jun-11 shadow fix — which affects a full re-run but not this rescore.)
- *Maybe it duplicates an existing register entry?* No. R03 is the pixel-scale confound; R04 is stale
  packaged splits; nothing in §4-§4h or §5 mentions the coreg sign vintage of the slim writeup, and
  `other-scripts.md:468-469` / `docs-consistency.md:737-738` both explicitly disclaim this check.

## Fix assessment

**superseded** by Brian's directive at `docs/CODE_REVIEW_2026-07-31.md:1725-1741`: do not retro-fix, date
each document and add a caveat header. Applying that here:

1. The suggested header line at :1733 ("all results use the pre-sign-fix labels; corrected, 'usable' is
   26 %, not 14 %") should say **"re-scoring the same predictions on the corrected labels gives 26 %; the
   run was not repeated, so this is a floor"** — otherwise the header itself ships a number that a future
   session will fail to reproduce with a re-run.

   0.276/0.904, usable 14→26 %, anti-signal 26→20 %, per-image ρ mean/median +0.151/+0.130 →

   that is the difference between a usable caveat and one that makes a reader discard the whole document.
3. It belongs on **both** `docs/modeling_slim.md` and `docs/classification_slimmer.md`, and one clause
   should be added to the reader entry point `docs/index.md:16`, which is where a reviewer arrives first

   title** by `_modeling_slim_figures.py:31-35`, so the caveat cannot travel with the figure. Either
   accept that (and say so in the header) or, if the figure is ever rebuilt, note that the builder reads
   the parquet blindly — there is no vintage check anywhere in the chain.
