### probes-utility-2 — the submitted PDF's Conclusions quote "agrees on over 90 % of its rich-tile calls" for an image where the worst possible ranking scores 74.6 % and a random one 79.7 %
- **Severity:** high (record correctness in a submitted, reader-facing document; Pattern B)
- **Liveness:** live-shipped (`docs/classification_slimmer.pdf`, `docs/modeling_slim.md`)
- **Confidence:** high
- **Where:** [scripts/probes/_modeling_slim_panels.py:84-92](../../scripts/probes/_modeling_slim_panels.py#L84-L92),
  [:118-120](../../scripts/probes/_modeling_slim_panels.py#L118-L120) (producer) ·
  `docs/modeling_slim.md:294-301`, `docs/classification_slimmer.md:202-207` and **:235-237**
  (Conclusions)

The figure's construction sets the prediction's positive count equal to the truth's positive count
(top-K with `K = n_rich_truth`), so the overlap between the two sets is **algebraically bounded** by
`max(0, 2K−n) ≤ agree ≤ K`. On the "good" panel (`ESP_053989_2260`, n = 656, K = 523, base rate
**79.7 %**) that means agreement can never fall below **390/523 = 74.6 %**, and a random ranking
delivers `K²/n = 417/523 = 79.7 %`. The doc reports **476 of 523 (91.0 %)** and the PDF's Conclusions
elevate it to "there *is* a CTX-recoverable signal — on the best images the model agrees with HiRISE
truth on **over 90 %** of its rich-tile calls". The genuine skill is 476 vs 417, i.e. **56 % of the way
from random to perfect**, not 91 % of the way from zero.

- **Failure scenario:** a reader of the submitted report's Conclusions takes "over 90 % agreement" as
  the headline positive result. Substituting the base-rate floor makes the same sentence read "91 %
  where 80 % is free and 75 % is the floor". The asymmetry is what makes this a record defect rather
  than a rounding choice: **the doc supplies the random baseline for the panel where it makes the model
  look bad and omits it where it would cut the apparent skill by four-fifths** — two paragraphs earlier,
  the anti-signal panel is correctly reported as "only 20 of 129 … well below the **~30 %** a random
  ranking would produce at this base rate" (and 129²/439 = 29.4 %, so that baseline is exactly right).
- **Evidence:**
  ```python
  # scripts/probes/_modeling_slim_panels.py:87-92  -- K is pinned to the truth count
  truth_eval = truth_eval.sort_values("pred", ascending=False).reset_index(drop=True)
  truth_eval["is_rich_pred"] = 0
  if n_rich_truth > 0:
      truth_eval.loc[:n_rich_truth - 1, "is_rich_pred"] = 1
  # :119-120
  n_agree_rich = int(((truth_eval["is_rich_truth"] == 1) &
                      (truth_eval["is_rich_pred"] == 1)).sum())
  ```
  Recomputed from `dataset_v2/modeling_slim_predictions.parquet` (using the banked
  `fractional_area_truth`, which is what the doc quotes):
  ```
  ESP_053989_2260: n=656 K=523 base=0.797 agree=476 (0.910)  random=417.0 (0.797)  floor=390 (0.746)
  ESP_046328_2180: n=439 K=129 base=0.294 agree= 20 (0.155)  random= 37.9 (0.294)  floor=  0 (0.000)
  ```
- **Self-refutation attempted:** (a) *Does the underlying conclusion die?* No — that image's per-image
  AUC is 0.880 and ρ +0.63, which establish real signal independently of the agreement statistic. What
  fails is the *number chosen to carry the claim*. (b) *Is the floor an artifact of my arithmetic?*
  `|A∩B| ≥ |A|+|B|−n` is exact for equal-size sets, and I verified 390 = 2·523−656 numerically.
  (c) *Is "top-K matched to the truth count" itself the defect?* No — it is a defensible, clearly
  captioned construction; it just makes the resulting overlap prevalence-dominated at an 80 % base
  rate, which is precisely the case the project's own `normalised_lift_at_top_k` docstring warns about.
  (d) *Already filed?* R26 is `precision@5%`'s base-rate cap in `src/modeling/evaluate.py`; this is a
  different statistic, a different producer and a different document. **Seventh instance of Pattern B.**
- **Fix:** report the pair, not the raw count — "476 of 523 (91 %) versus 417 (80 %) expected from the
  base rate alone, floor 390 (75 %)" — in both writeups, and drop or requalify the Conclusions
  sentence. Note that this statistic also carries defect **-1** (523/476 come from the pre-fix labels).
